`work/<교재 slug>/` 에 둔다. **등록(관리 기록 쓰기)은 하지 않는다** — 오케스트레이터가 검토 후 한 권씩 등록한다.

작업 폴더: `C:\Users\ljw09\Desktop\promblem_area` (여기서 명령 실행).
원본: **로컬 사본 `work\_src\<학년>\...`** 을 쓴다 (MYBOX `N:\개인\내문서\<학년>\...` 과 같은 파일·같은 폴더 구조, `work\_src\sources.json` 에 대응표).
**slug 는 `<학년>_<교재 이름>`** (예: `중3_쎈_3-1_1단원`) — 다른 학년 폴더와 겹치지 않게.
각 slug 폴더에 **`SOURCE.txt`** (원본 상대경로 한 줄, 예: `중3/신사고/쎈 3-1/쎈 3-1 1단원.pdf`) 를 꼭 둔다 — 등록 때 이 경로를 쓴다.

- 결과물은 `work/<slug>/` 안에만.
- 한글 경로에서 Git Bash 인코딩이 깨지면 PowerShell 을 쓴다 (`python book_tool.py ...` 는 어느 셸이든 됨).

## 도구 (`python book_tool.py ...`, 도움말은 파일 맨 위)
| 명령 | 용도 |
|---|---|
| `info <pdf>` | 쪽 수·크기·텍스트/스캔본 여부·PDF 목차 |
| `render <pdf> --pages 21,22 --out D [--dpi 70]` | 쪽 이미지 + 50pt 좌표 눈금 → Read 로 보고 단 경계·번호 위치 파악 |
| `probe <pdf> --pages 21,22 [--ocr]` | 숫자 조각의 x, y, 크기 (텍스트 PDF 는 --ocr 없이, 스캔본은 --ocr) |
| `extract <pdf> <layout.json> --out D [--pages 21-30] [--no-sheets]` | 좌표 추출 → D/problems.json, report.txt, sheets/*.png |
| `ocrtext <pdf> --pages 5 [--lang ko]` | 쪽 전체 OCR (목차·단원 제목 읽기) |
| `units <problems.json> <units.json>` | 단원 나누기 미리보기 |

layout.json 형식: `core/extract.py` 맨 위 설명. 단원 형식: `core/books.py` 맨 위 설명.
참고 예시: `work/쎈_공통수학1/layout.json` (스캔본, 4자리 번호, 짝수 쪽 좌우 밀림, 도장 포함 top_pad 16).
팁: 단 맨 아래 문제에 쪽 번호·꼬리말 조각이 딸려 오면 `body` 아랫값을 줄인다.

## 순서 (교재 한 권)
1. `info` → 텍스트 PDF 면 `"source": "text"`, 스캔본이면 `"ocr"`.
2. 목차·앞부분·중간·끝 몇 쪽을 `render` 로 본다. 파악할 것:
   - 문제가 있는 쪽 범위 (표지·목차·개념 설명만 있는 앞부분, **정답/해설이 있는 뒷부분은 빼기**)
   - 단 수와 각 단의 x 범위 (**가운데 구분선·옆 탭(단원 색띠)을 물지 않게**), 홀/짝 쪽 좌우 밀림 → `columns_even`
   - 문제 번호 모양 (`0103`, `01`, `1.`, `예제 1` …) → `label_regex` (첫 괄호 = 번호)
   - 머리말·꼬리말 위치 → `body`
3. `probe` 로 번호의 정확한 x(→ `label_x`)와 (텍스트면) 글자 크기(→ `text_size`)를 잡는다.
4. 10쪽 정도로 `extract --pages ...` → `sheets/*.png` 를 **Read 로 직접 보고** 확인:
   - 잘림(문제 아래·오른쪽), 옆·다음 문제 침범, 머리말 조각, 도장·서술형 표시 누락, **풀이/정답이 딸려 옴**
   - 고칠 것: `top_pad`, `bot_pad`, `gap_stop`(문제 안 여백이 커서 아래가 잘리면 늘림), `body`, `columns`
5. 전체 `extract` (먼저 `--no-sheets` 로 report 확인 → 문제가 정리되면 sheets 까지).
   report 의 ⚠ 항목을 처리:
   - **빠진 번호**: 그 쪽을 render 해서 보고, 진짜 문제면 `manual_labels` 로 추가 (y = 번호 윗끝)
   - **묶음 문제**(`[0125~0128] 다항식 P(x)를 다음 …` 공통 지시문 + 짧은 소문제들): 도구가 **자동으로 문제 하나**로 묶는다
     (단 왼쪽에서 시작하는 대괄호 머리글 `[a~b]`/`[a-b]` 를 찾음). report 의 "묶음 문제 N개" 확인,
     sheets 에서 머리글~마지막 소문제가 한 덩어리로 잘렸는지 본다. **건너뛰지 않는다.**
     머리글을 못 찾은 묶음 → `manual_groups` 로 추가. 묶음 아래로 다음 제목 띠가 딸려 오면 `group_gap_stop` 을 줄이고,
     소문제가 잘리면 늘린다. 머리글 모양이 다르면(괄호 없음 등) `group_regex` 지정.
   - 번호 영역 밖 경고는 보기 번호 등 때문에 흔함 — 빠진 번호가 없으면 무시해도 됨
   - **너무 작은 영역**: sheets 에서 확인
6. sheets 검수: **전체의 1/5 이상 + 경고가 난 쪽이 들어 있는 장은 전부** 직접 본다. 이상하면 설정 고치고 다시.
7. 단원: PDF 목차(`info`), 목차 쪽(`ocrtext` / `render`), 쪽 아래 꼬리말 단원명 등으로
   `units.json` 작성 (대단원 = `group`, 중단원 = `title`, `start` = 단원 제목 위치(쪽·단·y)).
   너무 잘게(유형별) 나누지 말고 **중단원 수준** (보통 한 권에 5~20개). `units` 명령으로 확인.
8. `work/<slug>/` 에 최종본을 둔다:
   - `layout.json`, `problems.json`(최종 extract 결과), `units.json`, `report.txt`
   - `NOTES.md`: 원본 경로, 텍스트/스캔, 문제 수, 건너뛴 쪽과 이유, 수동 추가 번호, 남은 문제점, 확신도(상/중/하)

## 무엇을 '문제'로 넣나
- 넣음: 학생이 푸는 번호 붙은 문제 (유형 문제, 연습문제, 단원 마무리, 서술형, 기출 등) + 묶음 문제(하나로)
- 뺌: 풀이가 바로 아래 붙어 있는 예제(풀이까지 잘리면 안 됨), 개념 설명, 정답·해설 부분
- 한 문제(또는 묶음)가 **다음 단/다음 쪽으로 이어지면**: 넘어간 조각을 problems.json 에 별도 항목으로 넣고
  `"continued": true` 를 붙인다 → 등록 때 **바로 앞 문제에 이어 붙어 한 문제**가 된다 (자르기 결과는 위아래로 이어 붙임).
  이어진 조각의 번호는 앞 문제와 같게 두면 된다. 묶음이 넘어간 경우 앞 묶음의 범위(num_end)를 줄이지 말 것.

## 그 밖의 설정 (고1 작업에서 추가됨)
- `label_min_h`: 번호 글자 최소 높이(pt). 스캔본에서 보기 '①12' 를 '012' 로 읽는 오인식 거르기
- `manual_groups`: OCR 이 못 읽은 묶음 머리글 직접 추가
- `drop_outliers: false`: 번호가 쪽·소단원마다 01 부터 다시 시작해서 정상 번호가 버려질 때
- 모아보기(sheets)는 앱과 같은 방식으로 자르므로 **회전된 PDF 도 똑바로** 보인다. 넓은(1단 편집) 교재도 앱에서 1단으로 출력 가능하니 그대로 두면 됨
- 이름만 다르고 내용이 같은 PDF 는 한 번만 작업한다 (오케스트레이터가 같은 좌표로 함께 등록)
- `render_clean: true`: 원본을 그대로 그리면 얼룩이 생기거나 글자가 빠지는 PDF (예: 고2 RPM 미적분1, 수력충전 대수).
  앱이 그리기 전에 쪽 내용을 메모리에서 정리한다(`core/pdfpage.py`). 모아보기가 깨져 보이면 `page.clean_contents()`
  를 적용한 그림과 비교해 보고, 그걸로 고쳐지면 layout.json 에 이 값을 넣는다 (사본 PDF 를 따로 만들지 않는다).
- 검수는 `python work\sample_sheet.py <slug> <출력폴더> 24` (최종 problems.json·render_clean 까지 앱과 똑같이 자름)
