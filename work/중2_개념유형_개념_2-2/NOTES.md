## 번호 찾기 (detect22.py → detected_labels.json → gen22.py → layout_*.json)
- 도구의 text/ocr 번호 찾기가 이 스캔본에서는 필수 문제 번호(보라 알약 안 흰 숫자)를 못 읽고 한 자리 번호도 자주 놓쳐서,
  `detect22.py` 가 쪽 그림(216dpi)에서 직접 찾음 (core.winocr 는 읽기만 사용, 코드 수정 없음):
  - 개념 쪽 필수 문제: 번호 띠(x 105~172)의 보라색 알약(높이 12.5~16.5pt, 폭 14~32pt)
  - 유제 N-k: 앞의 보라 막대 ▌(폭 < 3.5pt, 높이 7~15.5pt, 같은 줄 가장 왼쪽)
  - STEP1(쏙쏙 개념 익히기·한번 더 연습): 번호 띠(x 115~162)의 굵은 검은 숫자
  - STEP2(탄탄 단원 다지기): 두 단 번호 띠의 굵은 숫자 (두 자리 숫자 조각은 합침)
- 번호 값(`gen22.py`): 필수 = 소단원(01, 02…)마다 1부터, 유제 = 바로 앞 필수 번호, STEP1 = 이어지는 STEP1 쪽 묶음마다 1부터,
  STEP2 = 단원마다 1부터. OCR 로 읽힌 두 자리 번호(10, 12, 14, 16 …) 전부 순서와 일치. 글자층의 'N-k' 줄과 비교해 놓친 유제 없음.
- 서술형 완성하기 유제 1·2, 연습해 보자 1~4, 준비 학습 1·2 는 글자층 위치 + 쪽 그림으로 확인해 gen22.py 에 직접 적음.

## 남은 문제점

- (고침) 필수 문제·STEP1 의 왼쪽 옆날개는 뺌 — 아래 참고.
- 연습해 보자의 '풀이 과정' 빈칸은 대부분 빠짐(문제 본문은 온전).
- 번호 찾기를 다시 하려면: `python detect22.py <pdf> detected_labels.json` (몇 분 걸림) → `python gen22.py <slug폴더>` → 각 layout extract → merge_parts.py

## 왼쪽 옆날개 빼기 (검수 반영)
- 필수 문제·STEP1 항목의 bbox 왼쪽(x0)을 **번호(필수 = 보라 알약 왼쪽 끝, STEP1 = 숫자) x - 1.5pt** 로 옮겨 머리 상자·도움말·그림(옆날개)을 뺌.
  오른쪽 본문·그림은 그대로(표본 13·144·146·162쪽 등 직접 확인). 옆날개 끝이 1~3pt 남는 곳이 조금 있음.
- 방법: 레이아웃 단 x0 도 좁힘(gen22.py: 개념 129/114, STEP1 131/116: 홀/짝 쪽) + `gen22.py` 가 검출된 번호 x 를 `label_x.json` 에 적고,
  `merge_parts.py` 가 합칠 때 각 항목 x0 = max(단 x0, 번호 x - pad) 로 옮김.
- 다시 만들기: `python gen22.py <slug폴더>` → concept·yuje·step1(·필요한 레이아웃) extract →
  `python merge_parts.py <slug폴더> prep concept yuje step1 step2 essay practice` ("x0 fixed 243" 출력).
  extract 의 sheets 는 x0 옮기기 전 모양이므로 최종 모양은 problems.json 기준으로 확인.
