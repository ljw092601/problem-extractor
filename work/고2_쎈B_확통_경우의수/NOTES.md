- 원본: `고2/쎈/쎈B 1.경우의수.pdf` (로컬 사본 `work/_src/고2/쎈/쎈B 1.경우의수.pdf`), 18쪽, 595x841pt
- 스캔본 (OCR) → `"source": "ocr"`, PDF 목차 없음
- 쎈B 확률과 통계 중 'Ⅰ. 경우의 수' 유형뼈개기 부분만 발췌한 소책자. 정답/해설 쪽은 없음.
- 문제 번호: 중단원마다 `01`부터 다시 시작하는 2자리 (01 여러 가지 순열 01~46, 02 중복조합과 이항정리 01~55)
  → `drop_outliers: false`. 오른쪽 '쎈 0018' 같은 4자리 참조 번호는 label_x 밖이라 무시됨.

## 문제 수: 101개 (46 + 55)

- 사용: 3~9쪽, 11~18쪽

- 단·쪽 넘어가는 문제(`continued`): 없음

## 레이아웃 메모
- 단 경계는 픽셀로 실측: 홀수 쪽 왼단 51~290 / 가운데 구분선 301~309(비스듬) / 오른단 315~556 / 옆 탭 573~,
  짝수 쪽 왼단 57~297 / 구분선 310~312 / 오른단 323~563. 구분선이 오른단에 물리면 content_bottom 이 다음 번호까지 늘어나므로
  오른단 x 시작을 구분선 뒤(311/316)로 잡음.
- 유형 머리글 '유형 01' 의 작은 숫자(높이 7pt)는 `label_min_h: 8.5` 로 거름.
- `label_regex "^(0[2-9]|[1-5]\d)$"`: 보기 '① 1' 을 OCR 이 '01' 로 읽어 15·17쪽에 가짜 번호가 생겨 01 은 regex 에서 빼고
  진짜 01(3쪽·11쪽)은 manual_labels 로 넣음. 56 이상(예: '세'→'81')도 regex 로 거름.
- Windows OCR 이 실행마다 번호를 조금씩 다르게 읽어(8쪽 34, 13쪽 14 가 한 번은 잡히고 한 번은 빠짐) 재현성을 위해
  **101개 번호 전부 `manual_labels`** 에 넣음 (y = 번호 윗끝, 첫 추출 결과에서 가져옴). OCR 결과와 겹치면 OCR 쪽이 우선.

## 수동 처리
- 수동 추가 번호(manual_labels): 전부(101개). 실제로 OCR 이 못 읽은 것: 3쪽 01, 11쪽 01 (대표문제 뱃지), 8쪽 34, 13쪽 14 (실행에 따라).
- **problems.json 손질 1건**: 7쪽 오른단 31번 본문 '5의 배수…' 줄을 OCR 이 '54' 로 읽어 가짜 번호가 생기고 31번이 잘림.
  layout 설정으로는 뺄 수 없어(54는 18쪽의 진짜 번호) 추출 결과에서 가짜 54 항목을 지우고 31번 bbox 아랫끝을 그 끝(277.4)으로 늘림
  (`scratchpad/postfix.py`). layout.json 으로 다시 extract 하면 이 가짜 54 가 또 생기니 같은 처리가 필요함.
  → report.txt 의 "빠진 번호 7쪽 31→54", "너무 작은 영역 7쪽 54" 는 이 가짜 번호 때문이며 최종 problems.json 에는 없음.
