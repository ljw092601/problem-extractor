## ⚠ 중요: 원본을 fitz(MuPDF)로 그리면 쪽마다 큰 회색/검은 얼룩이 생김
- 원인: 보이지 않는 풀이 글자층(렌더 모드 3)이 글자마다 Form XObject(`/AGFA_TR 3`, 4250개)로 들어 있는데,
  그 Form 이 경로만 만들고 칠하기 연산자 없이 `h` 로 끝남. MuPDF 는 이 경로를 버리지 않고 바로 뒤의 칠하기
  (번호 앞 회색 '00' 등)와 합쳐 그려서, 쪽 크기만 한 숫자 모양 얼룩이 문제 글자를 덮음 (거의 모든 문제 쪽).
- **선생님 앱이 fitz 로 자르면 문제 그림이 가려져 보임** — `python work\sample_sheet.py 고2_RPM_미적분1 ...` 결과로 확인함.
  등록 전에 앱 쪽 처리 방법(깨끗한 사본을 원본 대신 쓰기 등)을 정해야 함. 코드는 고치지 않았음.
- 우회: `clean_pdf.py` 가 각 Form 끝에 `n`(경로 버리기)을 붙인 사본을 만듦 → 얼룩이 사라지고 좌표는 원본과 똑같음.
  `python work\고2_RPM_미적분1\clean_pdf.py <원본> <사본>` (사본은 scratchpad 에 만들어 씀. 사본의 sha256 은 원본과 다름.)
- 이 폴더의 좌표·모아보기 검수는 전부 이 **깨끗한 사본**으로 한 것 (얼룩이 있으면 내용 끝 판정도 틀어짐).

## 번호·묶음 찾기 (OCR 대신 벡터)
- 번호 `0034` 는 회색 '00'(CMYK K 0.4) + 색 숫자 경로. 회색 '0' 글자(높이 7.5~10pt, 단 왼쪽)를 `vlabels.py` 로 찾아
  (쪽 → 왼쪽 단 → 오른쪽 단 → 위에서 아래) 순서로 1~885 번호를 매겨 **885개 전부 `manual_labels`** (y = 번호 윗끝).
  OCR 추출 결과와 위치별로 대조해 번호가 전부 일치함을 확인 (OCR 은 108/741/121 같은 오인식이 있었음).
- 묶음 `[0001~0004]` 머리글: 초록 '[' 글자를 `vgroups.py` 로 찾고 머리글만 400dpi OCR 해서 범위를 읽음 → 59개 전부 `manual_groups` (`groups.txt`).
  범위 안 번호가 모두 머리글 아래 같은 단에 있는지 확인 → 단/쪽을 넘어가는 묶음 없음.
- 123쪽 0802 는 0801 옆(같은 줄)에 있어 묶음 [0801~0802] 안에 함께 들어감.
- 그래서 layout 은 `source: text` + 절대 안 맞는 `label_regex`/`group_regex` 로 두고 수동 목록만 씀 (OCR 불필요, 빠름).
  재생성: `mklayout.py vec` (base.json + vl.json + groups.txt → layout.json).
  (보조 스크립트 vlabels/vgroups/mklayout/leftover 는 작업 때 scratchpad 경로가 박혀 있음 — 다시 쓰려면 경로 S 만 바꾸면 됨.)
